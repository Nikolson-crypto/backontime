# Backontime — правила проекта

Глобальные правила `~/.claude/CLAUDE.md` действуют полностью; здесь только специфика проекта.

## Где что живёт
- GitHub = код, `docs/` = архитектура и ADR (версионируются с кодом).
- Notion = продуктовые документы (PRD, стратегия, исследование). Не дублировать — ссылаться.
- GitHub Issues = бэклог: эпики (`epic:E0`…), истории, задачи; `enabler` — техническая основа.
- Журнал сессий — `.claude/handoff.md`: дописывать датированные разделы без напоминаний, без секретов.

## Как работаем с кодом
- Перед изменением архитектуры прочитать код и `docs/architecture.md`; никаких переписываний «по памяти».
- Один стиль: ванильный JS (ES-модули после E0), без фреймворков, без TypeScript. Русские комментарии, английские идентификаторы.
- Тексты интерфейса только через ключи переводов (после E0), языки DA/EN.
- Тесты (Vitest) на расчёты времени и статусы; запускать перед коммитом.
- После значимых изменений обновить README и `docs/architecture.md`.
- Всегда `git fetch` перед правками: в `main` пушат из разных сессий.

## Стек
- Frontend: HTML/CSS/JS, Leaflet 1.9.4, OSRM public API (пеший маршрут), CARTO / Esri тайлы.
- Backend (ADR-002): Supabase — push-расписание, анонимные аккаунты, кэш зон Open Data DK.
- Хостинг фронта: GitHub Pages. Секреты: только `.env`, никогда в коде.

## Ночные прогоны
- Только задачи с меткой `ready` и чётким критерием «готово»; один прогон — один эпик или меньше.
- Работа в ветке `epic/EN-…`, никогда в `main`; PR открывается только при зелёных тестах.
- В PR: что сделано, чек-лист ручной проверки на телефоне (3–5 шагов).

## Продукт
- Первый город Копенгаген; аудитория — водители, приезжие, курьеры.
- Не делаем: оплату парковки (не конкурируем с EasyPark), тепловую карту до появления своих данных.
- Каждое правило парковки показывается с источником и датой; дисклеймер об ответственности обязателен.
